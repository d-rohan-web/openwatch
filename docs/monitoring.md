# Monitoring & dashboards

Four Grafana dashboards (generated by `infrastructure/monitoring/grafana/build_dashboards.py`, JSON in
`infrastructure/monitoring/grafana/dashboards/`):

| Dashboard | Answers |
|---|---|
| **Overview** | Are feeds healthy? How much is live / archived? Visitors and data served today; feed-health table; warnings & errors from the logs |
| **Situation** | How the situation changes over time: active alerts by severity, warnings by source, aircraft and satellites tracked, maritime/airspace notices, outages, quakes |
| **Visitors & traffic** | World map of visitors, top countries & cities, referrers, pages, browsers, OS, devices, status codes, response time, bandwidth and projected monthly egress vs the free 1 GB, recent-visitors log |
| **App** | Live viewers right now (browsers on the live stream), API requests/latency/errors by route, live-stream bandwidth, slowest feeds, archive size, process memory |
| **Server & cost** | CPU, memory, swap, disk, network, load, plus an **estimated Google Cloud bill** (IPv4 + egress beyond 1 GB, from real network counters) and egress per day |

One agent, **Grafana Alloy**, scrapes the collector/API metrics and host metrics and ships container logs plus Caddy's
access log. Where it ships depends on the profile:

## On the server → Grafana Cloud (free, nothing extra exposed)

Only Alloy runs on the VM (~80 MB, capped at 192 MB); data goes out to Grafana Cloud's free tier. No new IP, port or
firewall rule.

1. Create a free account at grafana.com and a stack.
2. Collect: Prometheus **remote-write URL** + **instance ID**, Loki **URL** + **user** (stack → Details), and an
   **access-policy token** with `metrics:write` and `logs:write`.
3. In Cloud Shell: `PROJECT=<your-project-id> bash scripts/deploy/grafana-cloud.sh` (prompts; the token is hidden and
   travels over SSH stdin into the VM's `.env`, mode 600).
4. In Grafana Cloud: **Dashboards → New → Import**, upload each JSON from `infrastructure/monitoring/grafana/dashboards/`,
   pick your `grafanacloud-…-prom` and `-logs` data sources.

## Locally → full stack

```bash
docker compose --profile monitoring up -d     # Prometheus, Loki, Alloy, Grafana
open http://localhost:39300                   # admin / GRAFANA_ADMIN_PASSWORD; dashboards are pre-loaded
```

## Visitor locations & privacy

Caddy's access log is enriched on the VM with the free **DB-IP Lite** city database (CC BY 4.0, "IP Geolocation by
[DB-IP](https://db-ip.com)", refreshed monthly by the `geoip-init` container): country as a label; city, coordinates,
browser, OS and device as structured metadata. **The last IPv4 octet is replaced with 0 before anything leaves the
server**, so Grafana only ever sees /24 networks and "unique visitors" is approximate.

## Actual Google Cloud billing (optional)

The *Server & cost* dashboard estimates the bill from network counters. For Google's real numbers:

1. Console → **Billing → Billing export → BigQuery export → Standard usage cost → Edit settings**: pick your
   project, create dataset `billing_export`, Save. (Data starts flowing within a day; BigQuery's free tier covers it.)
2. Console → **IAM → Service accounts → Create** `grafana-billing` with roles **BigQuery Data Viewer** and
   **BigQuery Job User** → Keys → Add key (JSON).
3. Grafana Cloud → **Connections → Add new connection → Google BigQuery** → upload the JSON key.
4. Add a panel (Table or Time series) with:
   ```sql
   SELECT DATE(usage_start_time) AS day, service.description AS service,
          ROUND(SUM(cost) + SUM(IFNULL((SELECT SUM(c.amount) FROM UNNEST(credits) c), 0)), 2) AS cost_usd
   FROM `<project>.billing_export.gcp_billing_export_v1_*`
   WHERE usage_start_time >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
   GROUP BY day, service ORDER BY day
   ```

## Editing dashboards

Change `build_dashboards.py`, run `python infrastructure/monitoring/grafana/build_dashboards.py`, re-import (Cloud) or
restart Grafana (local). Data sources are dashboard variables, so the same JSON works everywhere.
